# Web draft recovery (DR1, UNI-1014)

Lane decisions C15(3), wire contract C18, amendment C18a (after review finding RF-1). The web saves only on an
explicit user save (C10), so a crashed, closed or reloaded tab would lose every unsaved edit. Instead, every frame
keeps an **encrypted copy in this browser** while the document is dirty and offers it when the document is opened
again: it recovers after a crash, a closed tab or a reload, **until you sign out**. The copy is never sent to the host
or the server, never `api.save`, never a version.

## Wire (protocol README, "Draft recovery")

`init.recovery?: {key: CryptoKey, scope: string}`: AES-GCM 256, generated by the host with `extractable: false` and
**persisted by the host per user** in IndexedDB database `uniwork-office-frame-drafts`, store `keys`, key = user id
(structured clone, never exported; reused across page reloads and tabs); passed to the frame by structured clone in
`init` (again after a frame reload); `scope = "<userId>:<documentId>"`. Absent = recovery off (nothing written,
nothing shown). The host deletes the whole database on sign-out / session switch, which also removes the key, every
draft and the saved PDF signatures.

## Frame side

| piece                                    | file                                                                                               |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------- |
| store + crypto + writer/reader           | `web/docs/bridge/draft-recovery.ts`                                                                |
| shared database (stores, open, upgrade)  | `web/docs/bridge/frame-idb.ts`                                                                     |
| Restore / Discard prompt, default wiring | `web/modules/shared/recovery-prompt.ts` (shared dialog chrome, `webDraft*` strings in every shard) |
| test IndexedDB                           | `web/docs/bridge/testing/fake-idb.ts`                                                              |

- **The database is shared** with the host: stores `drafts` (frame), `signatures` (frame, PDF) and `keys` (host).
  Whoever opens first creates all three; every party opens **without a version**, and a party that finds a store
  missing reopens at `version + 1` to add it (`openFrameDb`). Opening with a fixed version would fail with a
  `VersionError` once the other side upgraded. Connections are short-lived and close on `versionchange` (the host's
  `deleteDatabase` is never blocked).
- Record key `scope + ":" + baseEtag + ":" + tabId`; value `{iv, ciphertext, baseEtag, savedAt, module, name}`.
  `tabId` is random per frame load, so a second tab (or a reload racing the tab it replaces) never overwrites another
  load's record. The full record key is the AES-GCM additional data, so a record cannot be replayed under another key.
- Writer: every 30 s while dirty and on `pagehide`, the bridge's "current bytes", overwriting this load's record for
  the open etag.
- Reader, before the document reaches the renderer: the **newest decryptable** record of the scope is offered (labelled
  "based on an older version" when its etag differs from the open one). This load's own records are never offered.
  **A record that does not decrypt (another key) or is damaged is skipped and never deleted**: it may belong to a live
  tab or to a later sign-in, and the sign-out `deleteDatabase` is the only cleanup. Restore = the draft bytes as a
  dirty document (the user still has to save; the head etag stays, so a newer version still surfaces as a save
  conflict); the restored record is re-keyed to this load (so a crash right after a restore keeps the edits) and the
  old record is deleted. Discard deletes the offered record. Escape keeps it.
- A landed save deletes **this load's** records of the scope; a conflict "Reload latest" does the same (the user
  dropped the edits). Other tabs' and earlier loads' records stay until restored, discarded or signed out.
- Only the init document has a scope: a document opened later inside the same frame is never drafted.

## Per module ("current bytes" / restore as dirty)

| module         | current bytes                                                                                                             | Restore                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Docs           | `provideDocBytes` (the docx the save path builds)                                                                         | open result `recovered: true` (renderer starts dirty)                                                        |
| Markdown, HTML | renderer `provideText` (committed text) → `encodeText`                                                                    | `consumeRecovered()` returns the replaced server text; Markdown marks dirty, HTML keeps it as the clean twin |
| PDF            | renderer `provideSaveRequest` (pending edits) applied to the working copy by the save core                                | draft = working copy, `consumeRecovered()` → renderer dirty with no edits; Save writes it                    |
| Slides         | `savePptx(session.opened)` (skipped in master view)                                                                       | `openSessionFromBytes({recovered: true})` → session dirty                                                    |
| Sheets         | the renderer's 30 s recovery tick (`recoveryCopy` on as trigger) → `writeWorkbookRecovery` → `transport.serialize` (pure) | open with `restoredFromRecovery` (Save = restore write-back); bridge keeps dirty until saved                 |

Known gaps: a record nobody restores or discards (e.g. a crashed tab whose user never reopens that document) stays
until sign-out; the offer shows the newest first. The `pagehide` write is asynchronous and may not finish; HTML style edits not yet committed and PDF editor
boxes still open are not in the copy until committed; Sheets (like the desktop) does not re-draft edits made after a
Restore until the next save.
