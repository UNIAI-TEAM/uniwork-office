# Web draft recovery (DR1, UNI-1014)

Lane decision C15(3), wire contract C18. The web saves only on an explicit user save (C10), so a crashed or closed
tab would lose every unsaved edit. Instead, every frame keeps an **encrypted copy in this browser** while the
document is dirty and offers it when the document is opened again. The copy is never sent to the host or the server,
never `api.save`, never a version.

## Wire (protocol README, "Draft recovery")

`init.recovery?: {key: CryptoKey, scope: string}`: AES-GCM 256, generated by the host per signed-in session with
`extractable: false`, held in host memory and passed by structured clone (again after a frame reload);
`scope = "<userId>:<documentId>"`. Absent = recovery off (nothing written, nothing shown). The host deletes the whole
database on sign-out / session switch (dev-uniwork `packages/core/office/draft-session-key.ts`).

## Frame side

| piece                                    | file                                                                                               |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------- |
| store + crypto + writer/reader           | `web/docs/bridge/draft-recovery.ts`                                                                |
| Restore / Discard prompt, default wiring | `web/modules/shared/recovery-prompt.ts` (shared dialog chrome, `webDraft*` strings in every shard) |
| test IndexedDB                           | `web/docs/bridge/testing/fake-idb.ts`                                                              |

- IndexedDB `uniwork-office-frame-drafts`, store `drafts`, out-of-line key `scope + ":" + baseEtag`, value
  `{iv, ciphertext, baseEtag, savedAt, module, name}`. The record key is the AES-GCM additional data, so a record
  cannot be replayed under another key. Connections are short-lived and close on `versionchange` (the host's
  `deleteDatabase` is never blocked).
- Writer: every 30 s while dirty and on `pagehide`, the bridge's "current bytes" (overwrite).
- Reader, before the document reaches the renderer: the open version's draft wins, else the newest draft of an older
  version (labelled "based on an older version"). A record that does not decrypt (another session's key) is deleted
  silently. Restore = the draft bytes as a dirty document (the user still has to save; the head etag stays, so a newer
  version still surfaces as a save conflict). Discard deletes the scope's records; Escape keeps them.
- A landed save deletes the scope's records; a conflict "Reload latest" deletes them too (the user dropped the edits).
- Only the init document has a scope: a document opened later inside the same frame is never drafted.

## Per module ("current bytes" / restore as dirty)

| module         | current bytes                                                                                                             | Restore                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Docs           | `provideDocBytes` (the docx the save path builds)                                                                         | open result `recovered: true` (renderer starts dirty)                                                        |
| Markdown, HTML | renderer `provideText` (committed text) → `encodeText`                                                                    | `consumeRecovered()` returns the replaced server text; Markdown marks dirty, HTML keeps it as the clean twin |
| PDF            | renderer `provideSaveRequest` (pending edits) applied to the working copy by the save core                                | draft = working copy, `consumeRecovered()` → renderer dirty with no edits; Save writes it                    |
| Slides         | `savePptx(session.opened)` (skipped in master view)                                                                       | `openSessionFromBytes({recovered: true})` → session dirty                                                    |
| Sheets         | the renderer's 30 s recovery tick (`recoveryCopy` on as trigger) → `writeWorkbookRecovery` → `transport.serialize` (pure) | open with `restoredFromRecovery` (Save = restore write-back); bridge keeps dirty until saved                 |

Known gaps: the `pagehide` write is asynchronous and may not finish; HTML style edits not yet committed and PDF editor
boxes still open are not in the copy until committed; Sheets (like the desktop) does not re-draft edits made after a
Restore until the next save.
