HOW THE LINKED SET WAS DETERMINED (UNI-2165, 2026-10-26)

 1. Build script. github.com/naptha/tesseract.js-core, tag v7.0.0: build.sh builds
    zlib, libtiff, openlibm, giflib, libpng, libjpeg, libwebp, Leptonica and
    Tesseract from git submodules (.gitmodules), Leptonica against the static
    codec libraries, and the Tesseract fork's CMakeLists.txt (WASM_BUILD)
    links libgif.a, libjpeg.a, libopenlibm.a, libpng.a, libtiff.a, libtiffxx.a,
    libwebp.a, libwebpdecoder.a, libwebpdemux.a and libz.a into the engine.
 2. Binary. The three .wasm files in the npm package are byte-identical to the
    files of the v7.0.0 tag (git blob ids tesseract-core.wasm 9a80423c827b,
    tesseract-core-simd.wasm 26fd0af4c984, tesseract-core-relaxedsimd.wasm
    d9295ca6ea7a). Their data sections contain code strings of every
    library below except openlibm (the wasm has no symbol names, so openlibm,
    a static library on the link line, is treated as linked):
      libpng    "Not a PNG file", png_do_* / png_* function names, IDAT
      zlib      "incorrect header check", "invalid distance too far back"
      IJG jpeg  "Unsupported JPEG process: SOF type 0x%02x", "Huffman table
                0x%02x was not defined", "JFIF"
      giflib    "GIF87a", "GIF89a"
      libtiff   "Not a TIFF file, bad version number %u", TIFFAdvanceDirectory,
                TIFFAppendToStrip, ... (100+ TIFF* names)
      libwebp   "VP8L", "VP8X", "ALPH", "Incorrect keyframe parameters.",
                "WebP decode failed"
      Leptonica pixRead*, "Leptonica coords ..."
 3. tesseract.js-core's README states that every dependency is unmodified
    except Tesseract.
